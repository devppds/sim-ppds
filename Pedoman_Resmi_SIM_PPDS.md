# BAB I
# PENDAHULUAN

## 1.1 Latar Belakang

Perkembangan teknologi informasi telah membawa perubahan besar dalam tata kelola administrasi lembaga pendidikan, termasuk pondok pesantren. Pengelolaan data secara manual memiliki berbagai keterbatasan, seperti kesulitan pencarian data, risiko kehilangan arsip, keterlambatan pelaporan, serta rendahnya efisiensi dalam proses administrasi.

Sebagai upaya mendukung transformasi digital dan peningkatan kualitas tata kelola lembaga, Pondok Pesantren Darussalam mengembangkan Sistem Informasi Manajemen Pondok Pesantren Darussalam (SIM-PPDS). Sistem ini dirancang untuk mengintegrasikan seluruh proses administrasi, keuangan, pengelolaan data, dan pelaporan operasional dalam satu platform yang aman, cepat, dan mudah digunakan.

## 1.2 Tujuan Pengembangan Sistem

SIM-PPDS dikembangkan untuk:

1. Meningkatkan efektivitas dan efisiensi administrasi pondok.
2. Menyediakan data yang akurat, terpusat, dan mudah diakses.
3. Mendukung transparansi pengelolaan keuangan.
4. Mempermudah penyusunan laporan operasional.
5. Menjaga keamanan serta keberlangsungan data lembaga.
6. Mendukung pengambilan keputusan berbasis data.

## 1.3 Ruang Lingkup Sistem

SIM-PPDS mencakup berbagai modul utama yang digunakan dalam pengelolaan pesantren, antara lain:

* Manajemen Data Santri
* Manajemen Data Pengurus
* Manajemen Data Alumni
* Keuangan dan Pembayaran Syahriah
* Arsip Digital
* Asrama
* E-Clearance Boyong
* Dashboard Eksekutif
* Pusat Kontrol
* Pos Kesehatan (UKP)
* Unit Usaha BUMP
* Operasional Seluruh Seksi

# BAB II
# PROFIL DAN GAMBARAN UMUM SISTEM

## 2.1 Identitas Sistem

Nama Sistem:
Sistem Informasi Manajemen Pondok Pesantren Darussalam (SIM-PPDS)

Versi:
Tahun Ajaran 2026–2027

Platform:
Web Application dan Progressive Web Application (PWA)

Pengembang:
Alumni Pondok Pesantren Darussalam Lirboyo

## 2.2 Deskripsi Sistem

SIM-PPDS merupakan sistem manajemen digital terpadu yang dirancang khusus untuk memenuhi kebutuhan administrasi dan operasional Pondok Pesantren Darussalam.

Sistem ini menggantikan berbagai proses pencatatan manual menjadi sistem digital yang lebih cepat, akurat, dan aman.

## 2.3 Modul Utama Sistem

Sistem menyediakan berbagai layanan utama, meliputi:

### 1. Data Santri
Pengelolaan seluruh data santri, termasuk identitas, status, kamar, dan informasi administrasi lainnya.

### 2. Data Pengurus
Pengelolaan data kepengurusan pondok, baik dewan harian maupun seluruh seksi.

### 3. Data Alumni
Pengelolaan data santri maupun pengurus yang telah menyelesaikan masa aktifnya.

### 4. Keuangan dan Syahriah
Pengelolaan pembayaran syahriah, pencatatan transaksi, laporan keuangan, dan monitoring anggaran.

### 5. Arsip Digital
Pengelolaan dokumen dan arsip lembaga secara digital.

### 6. Dashboard Eksekutif
Penyajian data strategis bagi pimpinan pondok untuk keperluan monitoring dan pengambilan keputusan.

# BAB III
# INSTALASI DAN AKSES SISTEM

## 3.1 Persyaratan Umum

SIM-PPDS dapat digunakan melalui komputer, laptop, tablet, maupun telepon seluler yang memiliki koneksi internet.
Disarankan menggunakan browser versi terbaru untuk memperoleh pengalaman penggunaan yang optimal.

## 3.2 Akses Melalui Browser

Pengguna dapat mengakses sistem secara langsung tanpa instalasi tambahan.

Langkah-langkah:
1. Buka browser Google Chrome, Microsoft Edge, Mozilla Firefox, atau Safari.
2. Masukkan alamat sistem: https://sim-ppds.pages.dev
3. Tunggu hingga halaman utama SIM-PPDS terbuka.
4. Klik tombol Masuk untuk menuju halaman login.

## 3.3 Instalasi pada Windows

Pada halaman utama tersedia tombol:
**DOWNLOAD .EXE (WINDOWS)**

Langkah instalasi:
1. Klik tombol DOWNLOAD .EXE (WINDOWS).
2. Tunggu hingga proses pengunduhan selesai.
3. Jalankan file installer yang telah diunduh.
4. Ikuti seluruh petunjuk instalasi.
5. Setelah selesai, aplikasi dapat dijalankan melalui shortcut yang tersedia.

Atau via PWA di Google Chrome:
1. Buka https://sim-ppds.pages.dev di Google Chrome.
2. Klik ikon Install (komputer dengan tanda +) di pojok kanan atas address bar.
3. Klik "Install". Shortcut otomatis muncul di Desktop.

## 3.4 Instalasi pada Android

Pada halaman utama tersedia tombol:
**DOWNLOAD APK (.APK)**

Langkah instalasi:
1. Klik tombol DOWNLOAD APK (.APK).
2. Tunggu hingga proses pengunduhan selesai.
3. Buka file APK yang telah diunduh.
4. Berikan izin instalasi jika diminta.
5. Lanjutkan proses instalasi hingga selesai.
6. Jalankan aplikasi melalui ikon yang tersedia.

Atau via PWA di Google Chrome:
1. Buka https://sim-ppds.pages.dev di Google Chrome HP Anda.
2. Ketuk ikon titik tiga (⋮) di pojok kanan atas.
3. Pilih "Tambahkan ke Layar Utama" (Add to Home screen).
4. Aplikasi siap digunakan seperti aplikasi native Android.

## 3.5 Instalasi pada iPhone dan iPad

Langkah instalasi:
1. Buka sistem menggunakan browser Safari.
2. Tekan tombol Bagikan (Share).
3. Pilih Tambahkan ke Layar Utama (Add to Home Screen).
4. Tekan Tambah.
5. Ikon SIM-PPDS akan muncul pada layar utama perangkat.

# BAB IV
# LOGIN DAN KEAMANAN AKUN

## 4.1 Sistem Autentikasi

Setiap pengguna diberikan akun sesuai jabatan dan kewenangan yang dimiliki.
Sistem menggunakan autentikasi berbasis username dan password untuk menjamin keamanan akses.

## 4.2 Format Username

Format username menggunakan pola:
`[jabatan].[nama_depan]`

Contoh:
* ketua.khoirul (Ketua Umum)
* sekretaris.wildan (Sekretaris Umum)
* bendahara.zidan (Bendahara Umum)
* keamanan.ihdal (Kasie Keamanan)
* pendidikan.sabiq (Kasie Pendidikan)
* wajar.bagus (Kasie Wajib Belajar)
* keuangan.isnanto (Kasie Keuangan)
* plp.arsy (Kasie PLP)
* humasy.azka (Kasie Humasy)
* kebersihan.alfa (Kasie KBR)
* pembangunan.alif (Kasie Pembangunan)
* media.zamzami (Kasie Media)
* takmirb.nurali (Kasie Takmir DS B)
* takmirc.taufiq (Kasie Takmir DS C)
* kesehatan.mafatih (Kasie Kesehatan)
* bump.malzumul (Kasie BUMP)
* jamiyyah.nur (Kasie Jam'iyyah)
* ketuablok.thohir (Kasie Blok)

Untuk anggota, format yang digunakan tetap sama sesuai seksi masing-masing (contoh: keamanan.ilham).

## 4.3 Password Awal

Setiap akun memperoleh password awal yang diberikan oleh administrator sistem (default: **123456**).
Pada saat login pertama, sistem akan mewajibkan pengguna mengganti password demi menjaga keamanan akun dan data lembaga.

## 4.4 Cara Login

1. Buka halaman login sistem (https://sim-ppds.pages.dev/login).
2. Masukkan username.
3. Masukkan password.
4. Klik tombol Masuk ke Sistem.
5. Pengguna akan diarahkan ke Dashboard sesuai hak akses.

## 4.5 Kebijakan Keamanan

Setiap pengguna wajib:
* Menjaga kerahasiaan username dan password (sebagai tanda tangan digital Anda).
* Tidak membagikan akun kepada pihak lain walau sesama pengurus.
* Melakukan logout setelah selesai menggunakan sistem.
* Mengganti password secara berkala.
* Segera melaporkan dugaan penyalahgunaan akun kepada administrator.

## 4.6 Lupa Password

Apabila pengguna lupa password:
1. Hubungi Sekretaris Umum atau Administrator Sistem.
2. Administrator akan melakukan reset password di menu Pusat Kontrol.
3. Pengguna wajib mengganti password kembali setelah berhasil login.

# BAB V
# STRUKTUR PENGGUNA DAN HAK AKSES

Setiap pengguna di SIM-PPDS diberikan peran dan wewenang (Role Level) yang menentukan bagian sistem mana yang dapat mereka akses. Berikut adalah struktur hak akses lengkap per jabatan:

## 5.1 Ketua Umum dan Ketua I, II, III
**Level Akses: ROOT / MUDIR / VIEW_ALL**

Ketua memiliki kewenangan penuh terhadap seluruh modul dan data dalam sistem.
* **Hak Akses Penuh:** Akses ke semua fitur operasional, data master, administrasi, dan finansial.
* **Menu Utama:** Dashboard, Data Santri, Data Pengurus, Data Alumni.
* **Keuangan:** Pembayaran SPP, Laporan Keuangan (Ledger, Neraca, Budgeting).
* **Eksekutif:** Dasbor Eksekutif, E-Clearance Boyong.
* **Lainnya:** Asrama, Arsip, Pos Kesehatan, Unit Usaha BUMP.
* **Operasional:** Akses Pantau Penuh ke seluruh seksi.
* **Konfigurasi:** Pusat Kontrol (manajemen pengguna/sistem) & Developer.

## 5.2 Sekretariat (Sekretaris Umum, I, II, III)
**Level Akses: SEKRETARIAT**

Tugas utama: Administrasi dan Manajemen Data
* **Menu Utama:** Dashboard, Data Santri (tambah, edit, hapus), Data Pengurus, Data Alumni.
* **Eksekutif:** Dasbor Eksekutif, E-Clearance Boyong (proses persetujuan).
* **Lainnya:** Asrama (pembagian kamar), Arsip (unggah dokumen).
* **Operasional:** Akses pantau (read-only) ke seluruh operasional seksi.
* **Konfigurasi:** Pusat Kontrol (reset password, tambah pengurus).

## 5.3 Bendahara Umum & Bendahara I
**Level Akses: KEUANGAN / VIEW_ALL**

Tugas utama: Pengelolaan Finansial Keseluruhan
* **Keuangan:** Mengelola Laporan Keuangan (Ledger Utama, Neraca, Monitoring Laporan Kas Seksi).
* **E-Budgeting:** Memproses pencairan anggaran proposal dari seksi-seksi.
* **Pembayaran:** Memantau rekapan pembayaran syahriah dari Seksi Keuangan.
* **Eksekutif:** Dasbor Eksekutif untuk memantau kesehatan finansial pondok.

## 5.4 Seksi Keuangan (Kasie & Anggota)
**Level Akses: RESTRICTED_SPP / KEUANGAN (Seksi)**

Tugas utama: Titik Penerimaan / Loket Pembayaran
* **Pembayaran SPP:** Bertugas menerima pembayaran dari santri dan menginput transaksi syahriah.
* **Tabungan Santri:** Mengelola penerimaan dan penarikan tabungan.
* **Fokus Pelayanan:** Sistem berfungsi layaknya Point of Sale (POS) khusus untuk kasir pondok.

## 5.5 Seksi Keamanan (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Penegakan Disiplin
* Mencatat pelanggaran santri di buku register digital.
* Membuat laporan insiden keamanan.
* Memantau status izin keluar/masuk santri.

## 5.6 Seksi Pendidikan & Penerangan (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Program Pembelajaran
* Mengelola jadwal pengajian dan kegiatan penerangan.
* Melakukan absensi ustaz dan rekapan nilai diniyah.
* Membuat laporan pendidikan bulanan.

## 5.7 Seksi Wajib Belajar & Murottil (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Kegiatan Jam Wajib Belajar
* Presensi kehadiran santri saat jam wajar/murottil malam.
* Penilaian ketertiban setiap blok.
* Evaluasi kelancaran kegiatan belajar.

## 5.8 Seksi Jam'iyyah (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Kegiatan Ekstrakurikuler
* Mengelola jadwal pelatihan (rebana, pidato, qiro'ah).
* Pelaporan manajemen kepanitiaan acara/PHBI.

## 5.9 Seksi PLP (Listrik & Air) (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Infrastruktur Utilitas
* Laporan pengecekan pompa air dan kelistrikan.
* Mengajukan proposal perbaikan infrastruktur.
* Rekap tagihan bulanan.

## 5.10 Seksi Humasy dan Logistik (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Layanan Umum
* Manajemen aset dan penggunaan barang logistik harian.
* Pengelolaan inventaris acara dan penyambutan tamu (Humasy).

## 5.11 Seksi Kebersihan (KBR) (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Sanitasi Lingkungan
* Penjadwalan piket roan (kerja bakti) santri.
* Penilaian kebersihan kamar dan blok.
* Pendataan alat-alat kebersihan.

## 5.12 Ketua Blok (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Kedisiplinan Asrama
* Mengelola administrasi dan melaporkan kondisi santri di masing-masing blok asrama.

## 5.13 Seksi Pembangunan (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Konstruksi
* Pelaporan progres proyek fisik pondok.
* Manajemen dan pengadaan bahan material bangunan.

## 5.14 Seksi Media dan Dokumentasi (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Publikasi dan Lab Komputer
* Penyimpanan arsip foto/video kegiatan pesantren.
* Pemeliharaan perangkat laboratorium media/komputer.

## 5.15 Takmir Masjid (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Pemakmuran Masjid (DS B & DS C)
* Menyusun jadwal imam, muazin, dan khotib.
* Laporan infaq Jumat serta kebersihan inventaris masjid.

## 5.16 Seksi Kesehatan (UKP) (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Layanan Medis
* Mencatat santri yang sakit atau dirujuk ke rumah sakit.
* Manajemen stok obat-obatan di Unit Kesehatan Pesantren.

## 5.17 Unit Usaha BUMP (Kasie & Anggota)
**Level Akses: OPERASIONAL / STAFF**

Tugas utama: Usaha Mandiri
* Laporan penjualan unit usaha (kantin/koperasi).
* Pengecekan stok barang dagangan.

# BAB VI
# DASHBOARD DAN NAVIGASI SISTEM

## 6.1 Dashboard Utama
Dashboard merupakan halaman pertama yang ditampilkan setelah pengguna berhasil masuk ke dalam sistem.
Berfungsi sebagai pusat informasi yang menyajikan ringkasan data dan aktivitas sistem secara real-time.

Informasi yang ditampilkan meliputi:
* Jumlah santri aktif, pengurus aktif, dan alumni.
* Grafik tren statistik pembayaran syahriah.
* Aktivitas terbaru pengguna (Activity Log).
* Notifikasi sistem dan papan pengumuman internal.
* Informasi tahun ajaran berjalan.

## 6.2 Navigasi Sistem
Sistem menggunakan menu navigasi terstruktur (Sidebar) berdasarkan hak akses pengguna.
* Setiap pengguna hanya dapat melihat menu yang sesuai dengan kewenangan jabatannya. (Misal: Kasie Keamanan hanya akan melihat menu Keamanan, tanpa akses ke menu Pendidikan).

## 6.3 Notifikasi Sistem
Notifikasi (berbentuk Toast Modern/Pop-up di bagian atas layar) digunakan untuk menyampaikan informasi penting:
* Berhasil / gagalnya penyimpanan data.
* Peringatan penghapusan data secara permanen.
* Pengingat laporan bulanan.

# BAB VII
# PENGELOLAAN DATA SANTRI

## 7.1 Tujuan Pengelolaan Data Santri
Modul Data Santri digunakan untuk menyimpan dan mengelola seluruh informasi santri secara terpusat untuk meminimalisir kesalahan administrasi.

## 7.2 Data yang Dikelola
Data santri meliputi:
* Nomor Induk Siswa Nasional (NISN)
* Nama lengkap & Tempat/tanggal lahir
* Asal daerah dan Alamat
* Nama wali santri dan Nomor telepon
* Kelas diniyah dan Asrama (Kamar & Blok)
* Status (Aktif / Boyong)

## 7.3 Menambah Data Santri (Bagi Sekretariat)
1. Masuk ke menu Data Santri.
2. Klik tombol **+ Santri Baru**.
3. Isi seluruh form biodata yang diperlukan.
4. Periksa kembali dan klik **Simpan**.
*Tersedia juga fitur Import Excel untuk memasukkan puluhan santri sekaligus saat ajaran baru.*

## 7.4 Mengubah Data Santri
1. Cari data santri melalui kolom pencarian.
2. Klik nama santri untuk melihat profil detail.
3. Klik tombol **Edit**.
4. Lakukan pembaruan (misal: pindah kelas/kamar) lalu klik **Simpan**.

## 7.5 Pencarian Data Santri
Sistem menyediakan fitur tabel cerdas untuk mencari berdasarkan: Nama, NISN, Kamar, Kelas, atau Status Santri.

## 7.6 Mutasi dan Promosi Alumni
Santri yang telah lulus dapat dipromosikan:
1. Buka profil santri.
2. Pilih "Promosikan ke Alumni".
3. Status santri akan berubah dari Aktif menjadi Boyong, dan otomatis masuk ke Data Alumni.

---

# BAB VIII
# PENGELOLAAN DATA PENGURUS DAN ALUMNI

## 8.1 Data Pengurus
Modul ini (dikelola Sekretariat) menampung direktori seluruh personel yang sedang menjabat di kepengurusan.

## 8.2 Penambahan Pengurus
1. Buka menu Pengurus.
2. Pilih **+ Tambah Pengurus**.
3. Masukkan Nama, Jabatan Utama (Ketua/Sekretaris/Seksi), dan Sub-jabatan (Kasie/Anggota).
4. Klik **Daftarkan Personel**. (Sistem akan membuatkan akun login secara otomatis).

## 8.3 Perubahan Jabatan (Reshuffle)
Jika terjadi pergantian struktur (mutasi), Sekretaris dapat mengedit profil pengurus tersebut dan mengubah seksinya tanpa harus menghapus akun.

## 8.4 Data Alumni
Terbagi menjadi dua tab utama:
* **Alumni Santri:** Berisi histori santri yang telah boyong.
* **Alumni Pengurus:** Berisi rekam jejak mantan pengurus di periode kepengurusan sebelumnya.
Berfungsi krusial untuk kegiatan silaturahmi besar dan pelacakan database jaringan alumni PPDS.

# BAB IX
# PENGELOLAAN KEUANGAN DAN SYAHRIAH

## 9.1 Tujuan Modul Keuangan
Mengelola transaksi penerimaan (syahriah) dari santri dan laporan pengeluaran (anggaran) secara akuntabel, real-time, dan meminimalisir kebocoran dana.

## 9.2 Pembayaran Syahriah (Loket Seksi Keuangan)
Fungsi POS (Point of Sale) untuk santri:
* Indikator warna: Hijau (Lunas), Merah (Nunggak).
* Input Pembayaran: Cari nama/NISN santri, pilih bulan yang akan dibayar, masukkan nominal, lalu klik **Simpan Pembayaran**.
* Cetak struk/tanda terima digital tersedia di profil santri.

## 9.3 Laporan Keuangan (Buku Besar / Ledger)
Dikelola oleh Bendahara Umum:
* Mencatat setiap Pemasukan (Aktiva) dan Pengeluaran (Pasiva).
* Transaksi dapat difilter, dicari, dan diekspor ke format dokumen.
* **Recycle Bin:** Keamanan bertingkat. Jika transaksi dihapus, ia masuk ke Recycle Bin terlebih dahulu untuk meminimalisir manipulasi.

## 9.4 Pencairan Anggaran (E-Budgeting)
Alur E-Budgeting:
1. Seksi mengajukan proposal di menu operasional.
2. Ketua menyetujui.
3. Di tab E-Budgeting (Menu Keuangan), Bendahara menekan **Cairkan Dana**.
4. Saldo Kas otomatis terpotong dan masuk menjadi catatan pengeluaran di Ledger.

## 9.5 Monitoring Laporan Seksi
Laporan Neraca otomatis terbentuk. Pimpinan dan Bendahara dapat memantau akumulasi pengeluaran vs pemasukan per seksi (seperti kas BUMP, kas Masjid). Tersedia tombol pengingat untuk menagih laporan kasie.

# BAB X
# PENGELOLAAN ASRAMA DAN ADMINISTRASI SANTRI

## 10.1 Data Asrama
Pemetaan fisik tempat tinggal santri. Memuat data:
* Blok Asrama
* Kamar
* Kapasitas Maksimal vs Penghuni Aktual

## 10.2 Penempatan dan Mutasi
Sekretariat dapat menyesuaikan penempatan santri melalui fitur Edit di menu Data Santri dengan memilih kamar baru dari opsi yang disediakan. Sistem akan mencegah kamar melebihi batas kapasitas wajar.

# BAB XI
# ARSIP DIGITAL DAN E-CLEARANCE BOYONG

## 11.1 Arsip Digital
Pusat pengarsipan tanpa kertas (Paperless E-Archive).
Kategori arsip:
* Surat Masuk / Surat Keluar
* Proposal Kegiatan
* Laporan Resmi / SK Kepengurusan
Fungsi unggah file memungkinkan dokumen berbentuk gambar atau PDF diamankan di server.

## 11.2 E-Clearance Boyong
Birokrasi digital untuk permohonan keluar pondok (lulus/boyong).
## 11.3 Tahapan Clearance
1. **Verifikasi Keamanan:** Santri harus bebas dari hukuman takziran.
2. **Verifikasi Keuangan:** Sistem mengecek jika masih ada tunggakan syahriah.
3. **Verifikasi Pendidikan:** Selesai program diniyah/wajar.
4. **Persetujuan Akhir:** Sekretaris menerbitkan Surat Boyong secara digital.

---

# BAB XII
# OPERASIONAL SEKSI DAN DIVISI

Sistem SIM-PPDS menyeragamkan alur kerja operasional. Setiap seksi memiliki menu unik yang menyajikan 3 fitur utama, yaitu:
1. **Catatan Operasional / Logbook harian**
2. **Formulir Pengajuan Proposal Anggaran**
3. **Pelaporan Bulanan**

Detail fokus fitur masing-masing seksi:

## 12.1 Seksi Keamanan
* Mencatat buku pelanggaran santri secara digital.
* Rekap histori pelanggaran per santri (terhubung dengan profil Data Santri).
* Izin kelonggaran jam malam.

## 12.2 Seksi Pendidikan & Wajib Belajar
* Penjadwalan program pendidikan.
* Evaluasi nilai dan pemantauan absensi (kehadiran) santri dalam kegiatan belajar malam.

## 12.3 Seksi Pembangunan & PLP
* Pemantauan progres konstruksi bangunan.
* Log pengadaan material dan pelaporan kondisi pompa air/kelistrikan yang rusak.

## 12.4 Seksi Kesehatan (UKP)
* Buku register pasien santri yang periksa.
* Catatan diagnosa ringan dan rujukan ke rumah sakit luar.
* Inventaris obat.

## 12.5 Seksi Humasy, Media, dan Jam'iyyah
* Dokumentasi foto kegiatan, manajemen tamu kunjungan, dan pembuatan kalender acara besar pondok.

## 12.6 Seksi KBR, Takmir, dan BUMP
* Pemantauan piket kebersihan blok, laporan infaq jumat, serta laba/rugi kantin atau unit usaha mandiri.

Semua laporan bulanan dari seksi ini akan bermuara dan dapat dibaca oleh Pimpinan melalui Dashboard Eksekutif.

# BAB XIII
# DASHBOARD EKSEKUTIF DAN PUSAT KONTROL

## 13.1 Dashboard Eksekutif
Dashboard Eksekutif diperuntukkan khusus bagi pimpinan pondok (Ketua Umum, Dewan Harian).
Fungsi utama:
* Analisis komprehensif kesehatan finansial pondok.
* Monitoring rekam jejak kedisiplinan dan pelanggaran tertinggi.
* Membaca dan mereview laporan operasional dari seluruh seksi tanpa perlu mengumpulkan berkas kertas.

## 13.2 Pusat Kontrol (Admin Panel)
Digunakan oleh Sekretariat dan Developer untuk konfigurasi inti sistem:
* **Manajemen Pengguna:** Menonaktifkan akun pengurus lama, mereset password, dan mengatur level akses.
* **Pengaturan Sistem:** Mengganti parameter seperti Tahun Ajaran Aktif.
* **Audit Trail:** Fitur forensik digital untuk memantau siapa mengubah/menghapus data apa pada jam berapa.

# BAB XIV
# KEAMANAN SISTEM, AUDIT LOG, DAN BACKUP DATA

## 14.1 Keamanan Sistem
Setiap pengguna diwajibkan untuk bertanggung jawab secara individu atas akunnya. Sistem mengenkripsi kata sandi pengguna untuk melindungi privasi.

## 14.2 Audit Log (Catatan Jejak Digital)
Untuk memastikan akuntabilitas, sistem akan merekam:
* Kapan dan IP Address mana pengguna melakukan login.
* Siapa yang menghapus transaksi keuangan atau mengubah data santri.
* Hal ini menjamin transparansi 100% dan mencegah manipulasi data internal.

## 14.3 Backup Data
Database (Cloudflare D1) di-backup secara otomatis di server secara berkala. Hal ini memastikan data santri dan keuangan tidak akan hilang meskipun komputer pondok mengalami kerusakan.
